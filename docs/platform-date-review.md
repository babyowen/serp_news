# 平台日期复核与评分时效

## 平台原则

所有关键词属于同一平台。江苏机关事务与公积金、养老以及以后新增关键词使用相同的日期核验、复核、评分和入库规则。关键词之间保留业务提示词、检索词和业务分类差异，不设置特殊日期待遇。

## 日期准入

四个搜索引擎结果都保留搜索日期原文及带时区的采集时刻。原文发布日期与目标日一致时通过；原文日期缺失时，可用严格换算到目标日的搜索日期兜底，并记录推定来源。原文明确早于目标日则排除；冲突、未来日期、无法解析或证据不足则进入待核验。正文仍需有效，日期通过不等于空正文可入库。

自动复核不会重新搜索，也不会用复核当天解释旧的“7h”。没有保存采集时刻的历史相对时间不直接放行。

## 自动复核

`main.py` 每次完成日常流水线后调用 `date_review.py`，处理所选关键词的到期任务。无须另建 cron。任务异常单独记录，不把当天已经成功的采集误报为失败。

- 首次待核验时保存 `date_review.first_seen`、`next_date`、`attempts` 和截止日期。
- 后续两个不同日期各重试一次，原文请求沿用站点提取器。普通续跑不绕过次数限制。
- 仍然不确定时标记 `archived`，保留正文、日期证据及原因，不要求每日人工处理。服务停机超过宽限期后归档，不积累无限补跑。
- 日期通过后为 `ready`，继续正文补全、评分和数据库写入。原批次日期和配置版本保持不变。
- 已成功评分先写入 JSON。数据库失败后复用评分，不重复调用模型；一条正文或评分失败不阻止其他已恢复新闻入库。
- 后续处理最多在三个不同日期尝试，耗尽为 `delivery_failed`，保留故障依据；有效业务 0 分不会当作评分失败。
- `delivered` 表示正文、评分和入库已完成。此次复核不自动补生成历史单条摘要；历史摘要可按现有摘要命令另行补充。

`output/date_reviews/` 仅保存活动任务索引；`last_run.report` 记录最近运行结果。原始批次 JSON 内的 `date_review` 保存最终状态，日期诊断的逐条记录包含它。`pending` 是日期结论，`archived` 是停止自动重试的处理状态，两者可以同时存在。

新平台诊断路径为 `output/<日期>/diagnostics/dates_<关键词哈希>.json`；已有江苏机关事务诊断文件名 `government_affairs_dates.json` 为运维兼容保留，规则完全相同。MySQL 和前端本次不新增日期状态列，证据与重试状态在 JSON 和日志中可查。

## 共用评分规则

`scoring_policy.py` 的规则在调用时追加到所选业务提示词，覆盖有专属提示词、使用默认提示词以及以后新增的关键词。生产业务提示词存储不被覆盖。

规则：主要事件明确发生在采集基准日期七天以前，且没有近期实质进展，最高 2 分；原本 0–1 分不抬高。正文引用的历史政策、背景年份不单独触发降分；日期不明不猜测。恰好七天不触发“超过七天”上限。原文发布时间有明确一致证据且超过七天时，代码也执行上限。

每次请求传入原采集日期及日期证据。所有关键词使用严格单字符评分解析，失败记录 `score=null`、`score_status=failed`、原因与尝试次数，不伪装业务 0 分。为了让时效规则实际运行，批量评分不再用标题规则直接跳过模型；原 `NEWS_RULE_BASED_SCORING` 配置保留用于兼容，不删除用户配置。

`government_affairs_scoring.py` 暂保留历史模块名，内部已是所有关键词共用实现。评测指纹包含公共规则源码，旧评测报告不能冒充新增规则后的验证结果。

## 运行与边界

```bash
# 由主程序自动调用，也可手动处理到期任务（会请求原文，必要时调用模型并写数据库）
python date_review.py --keywords 公积金 养老

# 隔离测试，禁止外网、真实模型和生产数据库
python run_config_tests.py
```

自动队列只处理已登记的新待核验记录，不扫描并重评整库历史数据。原有已完成评分保持不变。旧批次如果缺少日期证据，重新执行评分或入库会被日期闸门拦截，应先完成正文日期核验。

离线测试验证参数、状态转换和调用边界，不证明模型对任意旧事件的识别准确率，也不代表生产已经部署。
