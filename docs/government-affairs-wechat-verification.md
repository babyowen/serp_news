## 最终审阅后的进程生命周期修复

整分支审阅发现：父进程被强制终止时，业务子进程仍可能写入，但父进程独占的同日锁和运行租约已释放。修复将这两个描述符通过 `pass_fds` 显式传给当前业务阶段，并在提交并发评分时复制上下文。父子进程仅关闭自己的描述符副本，最后一个工作子进程退出后锁才释放；无关描述符不继承，日期复核仍在锁作用域之外。

新增8项真实子进程回归，通过隔离的 `main.main()`、shell 和本地写入脚本验证：

- 正文、官微增量评分、两路并发评分、入库、摘要共5种场景下，SIGKILL 父进程后同日锁继续排斥新任务，检查器保持“运行中”；最后一个子进程退出后锁可重新获取，检查器将记录标为“中断”。这5项在修复前均因同日锁提前释放而失败。
- 正常退出和失败重试均释放锁，独立日期复核可重新获得同日锁；无关的可继承描述符不会传给业务子进程。
- 关闭官微功能时，不创建官微锁或台账，原有业务阶段和复核继续完成。

## 运行边界

- 接口已收到请求但未返回可读费用时，费用无法从响应确认。收到响应后如在检查点落盘前中断，续跑可能需要再次请求该页或正文。
- 数据库提交确认丢失后，新增数量以未知显示。采集按文章计数，新增入库按已确认提交的新行计数，摘要按实际更新的数据库记录计数。
- 飞书接收请求后如应答丢失或本地确认未落盘，超过 API 的一小时 UUID 去重窗口后补发可能重复。已落盘的发送确认支持去重。
