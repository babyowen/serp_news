# Bing 新闻渠道：2026-10-08 诊断与修复

## 问题及原因

新加坡 `/www/wwwroot/serp_news` 在 `3bc1ca8` 上执行的 10 月 8 日凌晨批次，业务日期为 10 月 7 日。8 个主主题的 Bing 都失败，错误是访问 **SerpAPI** 等待响应超过 15 秒；不是直接访问 Bing 网站被拒绝。

`output/error_log.txt` 有 39 条当天 `bing_news` 最终失败记录：其它 7 个主题合计 17 个检索词各失败一次；江苏机关事务 11 个词各执行两轮。每轮函数内部又尝试最多 3 次。39 是最终失败日志条数，不是 HTTP 请求次数。

所有主题均保留其它来源数据。机关事务额外将任一来源失败视为该检索失败，主流程再重试整次四源检索；其它主题原来没有同样的失败状态，导致错误只在机关事务的阶段汇总中明显出现。

本次服务器最小对照请求，没有运行流水线或写业务数据库：

| 请求 | 结果 |
| --- | --- |
| 原 `interval="8" sortbydate="1"`，机关事务管理、养老，读取等待 75 秒 | 两条均 `ReadTimeout`，约 75.1 秒 |
| 同组合查询的返回结果 | HTTP 503，`search_metadata.status=Error`，上游处理约 90.08 秒 |
| 养老，无 `qft` | HTTP 200 / Success，12 条，约 4.21 秒 |
| 养老，仅 `interval="8"` | Success，6 条，上游处理 1.09 秒 |
| 养老，仅 `sortbydate="1"` | Success，12 条，上游处理 0.98 秒 |
| `mkt=zh-CN` | HTTP 400，明确提示该 Bing 市场不支持 |
| 最终修复参数：`mkt=en-US`，仅 `interval="8"`，机关事务管理 | Success，11 条，约 1.05 秒；业务日期过滤后 2 条 |
| 相同修复参数，养老 | Success，12 条，约 2.28 秒；业务日期过滤后 3 条 |

对照支持“当前组合筛选与排序请求在上游处理异常”的判断，不能简单归因为 15 秒设置过短，也不能声称 Bing 服务全球宕机。SerpAPI 内部为何对该组合失效尚无服务商说明。真实验证是两个关键词，不代表所有检索词全天稳定性已经得到证明。

官方依据：[Bing News 参数](https://serpapi.com/bing-news-api)、[状态与错误语义](https://serpapi.com/api-status-and-error-codes)、[读取已有搜索结果](https://serpapi.com/search-archive-api)。`Success` 加空列表是正常零结果，不能将错误或超时也算作零结果。

## 修改行为

- Bing 只设置覆盖业务日的时间窗口，不把 `sortbydate` 与 `interval` 拼在一起。当天/近一天用 24 小时，跨过前一天零点时用 7 天，更久分别用 30 天或取消窗口；精确业务日期仍由本地过滤决定。
- 明确使用支持的 `en-US` 市场，检索词不翻译。它固定市场及日期语言，避免请求默认区域返回当前解析器不支持的日期语言；可能改变来源分布，需要自然批次观察，不能仅以原始条数判断改善。
- 保留 SerpAPI 原始来源与采集时刻。新闻日期按原采集时刻换算，不按后续核验时刻重新解释。
- 所有主题的逐检索日志增加 `[来源状态]`：`ok` 为 API 返回新闻，`empty` 为正常空结果，`failed` 为调用失败；数量另由原 `[来源]` 行记录过滤后的目标日数量。`ok` 不承诺一定有目标日新闻。
- 来源失败时，所有主题明确打印警告，并在脚本结束信息标注“来源不完整”；成功来源结果仍保留。本轮保留既有主流程的退出及续跑策略，没有扩大为各阶段失败策略重构。
- Bing HTTP 异常仅输出异常类型与 HTTP 状态，不输出可能含 API 密钥的完整请求 URL。重试仍有上限，不靠无限等待隐藏失败。

业务关键词、提示词、模型、日期闸门、评分与周报流程均不改变。没有增加评分自检模型。历史结果不自动重评、补抓或覆盖。

## 验证与上线边界

隔离回归通过 `python -B run_config_tests.py` 执行，禁止网络、真实 `.env`、生产配置及业务库。回归覆盖多个现有/未来主题、窗口边界、原始来源及采集时刻保留、目标日过滤、来源失败与正常空结果区分，以及 HTTP 异常不泄漏密钥。

修复前基线为 742 项、12 项子测试、19 项日志检查通过；新增 15 项回归，其中参数、来源身份/状态及异常脱敏用例先在旧实现复现失败，另补全主题日志案例。最终完整隔离回归为 **757 项、12 项子测试、19 项日志检查通过**，`git diff --check` 通过。
