### 2.2 采集、归集与去重

- 正式启用后加入现有每日任务；单专题入口为 `python main.py YYYY-MM-DD --keyword '江苏机关事务'`。省略日期时沿用处理前一日数据的行为。这里及下文的运行命令均在功能开发完成后使用。
- `keyword` 固定为 `江苏机关事务`，`search_keyword` 保存配置顺序中首次保留下来的实际命中词；不改成所有词的拼接字符串。
- 复用现有判重：采集合并按去空白后的 `title + link` 保留首条，评分按有效 `link` 保留首条，入库按主关键词范围内 `title + link` 并辅以同标题查重。跨专题允许保留，首次命中来源不被后续重复命中覆盖。
- 不承诺跨站转载、近似标题的语义聚类；不同阶段丢弃数量可不同，验收须分别核对，不能要求 JSON 条数和数据库行数无条件相等。
- 记录各检索词的成功、空结果和失败。空正文在评分侧记为无有效内容，数据库沿用跳过空正文规则。搜索失败、正文提取失败与业务不相关分开统计。
- 正式运行继续使用现有采集源、日期过滤和黑名单。上线预览检查现有过滤配置是否影响样本召回，发现问题单列差异，不静默修改其他主题配置。

### 2.3 摘要与集中浏览

- 摘要条件为 `ENABLE_ITEM_SUMMARIZER=1`、`score >= 3`、有效正文、尚无摘要；正文去除首尾空白后长度 `<= 500` 时直接保存原文，较长正文调用现有通用单条摘要。
- 摘要忠于原文中的主体、措施、适用对象、时间和数据；不得补出政策效力、成效、地域或推广结论。低分新闻不要求摘要，已有摘要不重复生成。
- 首页提供 `江苏机关事务` 专题及数量；无记录也显示专题和明确空状态。保留日期、评分、来源、API 筛选及 50 条分页，切换专题回第一页，翻页保留筛选条件。
- 列表维持短摘要预览；在原页面增加“查看摘要/检索来源”展开或弹窗，按需读取单条完整 `short_summary`、首次 `search_keyword` 和原文链接。摘要为空显示“暂无摘要”，不能单凭空值断言处理失败。
- 列表不批量拉取长正文或完整摘要；不建独立新闻页面，不扩大首页每页条数。`score IS NULL` 显示“未完成评分”，不展示成 0 分。

### 2.4 新闻量变化提醒

复用 `news_volume_alert.py` 和原有通知渠道：全量为该专题数据库记录数，高分为其中 `score >= 4` 的数量；按 `fetchdate` 比较，日期口径采用 Asia/Shanghai。已入库但评分未完成的记录属于全量，不属于高分。

明确沿用现有基线算法，防止开发时另造一套规则：

1. 查目标日期及前 7、14、21、28 天；使用同星期最多 4 个历史样本。
2. 历史总量为 0 的日期按现有机制视为缺失，不补 0 拉低均值；总量大于 0、高分为 0 是有效样本。
3. 无有效历史样本时记录“暂无历史基线”，跳过涨跌判断，不列为骤降或正常稳定。
4. 有 1—3 个样本时按实际样本数求均值，并显示样本数；不假装已有四周基线。不新增等待四周才提醒的规则。
5. 保持绝对变化率严格大于 20% 才触发；高分基线为 0 且当天大于 0 按现有“新增”口径处理。

此提醒描述搜集量变化，不代表业务或舆情风险。只读新闻计数不能区分“真实无新闻”与“任务没有完成”，必须结合各阶段日志解释，不能由数量反推采集成功。

## 3. 评分标准与业务边界

### 3.1 进入 3—5 分的前提

满足以下任意一项，并且正文包含实质业务事实：

1. 主要主体为机关事务管理局、服务中心、主管部门或承担同类职责的单位，主要事件属于第 2.1 节业务。
2. 主要内容直接适用于党政机关、行政事业单位或公共机构运行保障，属于相关政策、制度、标准、改革、监督检查、项目或管理实践。

仅在背景提及、仅词语命中、适用对象不明，以及机关事务部门的纯党建学习、志愿活动、参观慰问、人事任免、空泛会议，均不得超过 2 分。报道含党建或会议字样但主要事实是实质业务举措时，按主要事实重新判断，不按敏感词一刀切排除。

### 3.2 分值

| 分数 | 阅读含义 | 定分依据 |
| --- | --- | --- |
| 5 | 重点关注 | 全国重大政策法规、规划、国家标准、全国性制度改革、中央重大部署，或具有全国普遍适用性、显著制度影响的重要事件 |
| 4 | 关注借鉴 | 省级、副省级或重要城市的实质政策标准、系统性改革；跨地区推广试点；重大资产盘活、数字化平台、保障项目；较大范围监督检查、典型经验与重要成果 |
| 3 | 日常参考 | 地市、区县或具体单位事实明确的资产调剂、公物仓、用房用车、节能、住房、接待、后勤、运行成本等日常业务，影响或创新性一般 |
| 2 | 关联有限 | 弱关联、对象不明确、缺少实质业务事实的介绍和非业务活动 |
| 1 | 明显不相关 | 主要事件不属于机关事务，或企业宣传、产品推广、一般商业活动 |
| 0 | 无有效参考信息 | 正文为空、无可识别新闻事实，或完全无关且没有有效关联信息 |

层级只是重要性参考：国家级单位的一般活动不自动得 5 分，省级部门的普通业务动态也可为 3 分。没有证据时不推断“重大”“全国适用”“可推广”。

### 3.3 必须执行的封顶规则

| 内容 | 允许进入相关业务的条件 | 不满足时上限 |
| --- | --- | --- |
| 国企改革、国资委监管、股权交易、企业资产、自然资源 | 有行政事业单位资产或机关事务资产管理的直接事实 | 明显无关 0—1；背景弱关联至多 2 |
| 商业楼宇、房地产、普通住房、保障房、公积金 | 明确为党政机关办公用房或机关住房保障 | 明显无关 0—1；弱关联至多 2 |
| 汽车产品、市场、网约车、私家车、交通治理 | 直接涉及党政机关公务用车管理或保障 | 明显无关 0—1；弱关联至多 2 |
| 工业、企业、住宅节能；居民碳普惠、商业低碳营销 | 明确涉及公共机构节能、绿色办公、机关公务出行或机关事务管理 | 至多 2 |
| 学校、医院一般环保活动 | 有公共机构节能制度或实质管理实践 | 至多 2 |
| 商务、旅游、外交礼宾、婚宴餐饮接待 | 属于党政机关国内公务接待管理、监督或保障 | 0—1 |
| 学校、医院、军队、社区、园区、企业的一般后勤物业食堂采购 | 直接服务党政机关办公运行，或明确纳入机关事务管理、公共机构节能制度 | 一般无关内容 0—1 |
| 一般财政支出、企业成本、机构经营成本 | 有机关运行经费、资产或服务管理事实 | 至多 2 |

学校、医院的行政事业单位资产调剂、公共机构节能管理属于正向边界样本；机构性质本身不能证明相关，也不能成为一概排除的理由。

```text
3. 汽车产品、市场、网约车、私家车、一般交通治理不等于党政机关公务用车管理；明显无关最高1分，弱关联最高2分。
4. 工业、企业、住宅、居民一般节能降碳不等于公共机构节能；碳普惠若不直接涉及公共机构管理或机关运行，最高2分。
5. 学校、医院的一般环保宣传，未涉及公共机构节能制度或实质管理实践，最高2分。
6. 商务、旅游、外交礼宾、婚宴餐饮接待不等于党政机关国内公务接待，最高1分。
7. 学校、医院、军队、社区、园区、企业的一般后勤、物业、食堂或采购，最高1分；明确服务党政机关办公运行或纳入机关事务管理、公共机构节能制度时，再判断直接相关性。
8. 学校、医院等公共机构涉及公共机构节能制度、行政事业单位资产实质管理的报道可以纳入，不得因单位类型一概排除。
9. 一般财政支出、企业成本、机构经营成本不能代替机关运行经费、资产和服务管理事实；未直接相关最高2分。
10. 机关事务部门的纯党建学习、志愿活动、参观慰问、人事任免、空泛会议，无实质业务事实时最高2分。

【判断顺序】
1. 正文是否有可识别的新闻事实；没有则0分。
2. 识别主要主体、适用对象和主要事件。
3. 判断直接相关性；不满足则在0—2分内判断。
4. 检查排除情形，遵守具体上限；某类最高1分时不得放宽为2分。
5. 仅对直接相关的新闻按政策层级、影响范围、制度价值和事件重要性评3—5分。
6. 无法确认时从严评0—2分，不得猜测。
最终只输出一个ASCII整数字符：0、1、2、3、4、5。不附解释、标点或其他内容。
```

</details>

User Prompt 复用 `NEWS_SCORE_PROMPT`，实际搜索词进入原 `keyword` 占位符。评分只需一次模型判断，不增加独立的相关性模型阶段；评测理由由样本标注者和复核人员记录，不要求评分模型额外输出解释。

### 5.3 严格评分、异常与重试

现有 `int(score_str[0])` 会接受 `5分`、`10`，现有标题规则也可能绕过专属提示词。本专题必须统一经过以下入口，覆盖批量、单条测试及重评。

建议接口落在 `news_scorer.py`：

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class ScoreResult:
    score: int | None
    status: str          # ok / empty_content / failed
    error_code: str | None
    attempts: int
    raw_response: str | None

def parse_government_affairs_score(raw: str) -> int:
    text = raw.strip()
    if text not in {"0", "1", "2", "3", "4", "5"}:
        raise ValueError("invalid_score_output")
    return int(text)

```

另提供 `score_news_result(title, content, keyword, main_keyword, max_retries=3, retry_interval=5) -> ScoreResult`，复用现有消息构建、客户端池和 `llm_settings`；其他专题仍保留原接口行为。函数按以下确定行为实施：

- 本专题必须找到专属且 active 的映射，否则明确配置失败，不回退通用提示词。不能因为 `search_keyword` 变化切换 system prompt。
- 空值或纯空白正文直接 `score=0, status=empty_content`，不调用模型。以实际正文为准，不仅检查 `wordcount == 0`；非空正文与错误的字数元数据不一致时不据此跳过分析。
- 正常返回只接受去除首尾空白后的单个 ASCII `0`—`5`。`5分`、`10`、`6`、`-1`、`3.0`、全角数字、JSON、解释文字、空响应或缺少 choices 都进入异常流程。
- 网络、鉴权/额度、超时、输出格式、上下文超限分别记录；重试沿用有界策略，单次评分调用最多 3 次，已知不可恢复错误不无意义重试，不新增循环补跑任务。
- **本专题失败采用 `score=null, status=failed`，不伪造 0 分。** 复用数据库已有可空 `score` 字段，不新增表或列。`status/error_code/attempts` 保存在 scored JSON 和日志；原始回答用于隔离评测报告，常规日志不复制新闻全文或凭据。
- 排序兼容空分并放在有效分之后；0—5 分分布只统计有效结果，另列空正文数、失败数。空正文的合法 0 不能用于掩盖正文抓取失败；抓取失败仍记在上游阶段。
- 新专题存在失败条目时评分脚本返回失败。`main.py:execute_scoring` 和评分脚本不能仅凭 `_scored.json` 存在就认定完成；普通续跑报告仍有失败，显式 `--rescore` 只处理该专题 `score is None` 的失败条目，成功条目含有效 0 不重复付费。
- 重评脚本只更新 JSON。随后运行同日期、同专题的 `write_to_mysql.py --date YYYY-MM-DD --keyword '江苏机关事务'` 完成同步，也可由后续主流程的入库阶段同步。当前 `update_scores_from_json` 没有接入实际导入入口，必须在本专题导入成功后显式调用，并让异常传递到退出码。
- 同步仅更新该专题对应 `keyword + title + link` 的空分记录，允许写回有效 0；已存在的非空评分不覆盖。修正现有 `if not score` 跳过 0 的分支，并给此范围加回归。其他专题的评分策略和重评行为保持兼容。

结构化结果是程序内部元数据，模型仍只输出一个整数，不增加解释型输出协议或第二次审核模型。

### 5.4 采集及摘要失败记录

- 对新专题，11 个检索词分别保留最终成功/空结果/失败及原因；部分检索词失败允许保留已取得新闻，但专题采集结果不能报全成功。恢复失败检索词由人工安排，不自动补历史日期。
- 将本专题检索状态原子写入 `output/<date>/diagnostics/government_affairs_fetch.json`，包含日期、配置版本、各词状态、数量和脱敏错误。诊断文件放在子目录，避免被现有按日期扫描新闻 JSON 的页面误认为新闻。合并文件存在而诊断记录失败/缺失时不能直接跳过报成功；有失败的续跑明确提示人工恢复，不能静默复用不完整结果。
- 空正文、提取报错、评分失败、摘要失败、数据库写入失败分别记录，避免都归到“新闻无关”。能复用已有日志时不建额外存储系统。
- 摘要沿用现有有限处理轮次，对本专题按条目最终状态统计。重试后已成功的条目不继续计为最终失败；仍失败时返回失败并保留原始错误。正常跳过、功能关闭与失败分开。
- 聚合流程继续处理可处理的记录并如实返回失败状态。日志/产物验收不能被笼统的“7/7”代替；本期只修正影响新专题交付的条目状态，不重构整个调度器。
