# 官微评估页与飞书可读性 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development; report generation and notification changes are separate tasks.

**Goal:** 用已完成的一周真实回填制作本地评估 HTML，并将官微飞书结果改为读者能直接理解的结果叙述，展示新增来源地区。

**Architecture:** 评估页只读冻结回填证据，提供来源地区、日期、分数、去重结果及原文/摘要筛选和本地评审标记。通知在现有台账中增加可选、经验证的读者视角统计，按新增保留行归因摘要和来源；兼容旧台账，不改变业务处理及调度。

**Tech Stack:** Python 3.11+；现有 Feishu 卡片 JSON；无外部依赖的 HTML/CSS/JavaScript。

**Spec:** 用户本轮明确要求评估 HTML、人类视角的飞书叙述与图标、隐藏运行 ID、了解哪些地区有文章进入。

## Global Constraints

- 不重新采集、评分、摘要或写业务数据库；不修改分数、关键词、标题、正文、入库门槛与既有生产记录。
- 评分低于3分保留原文，无需摘要；达到摘要条件的短正文直接采用，计为摘要就绪，不能称为“无需处理”。
- 新增条数与新增摘要分类均以实际保留行计算，重复候选和旧行不混入新增的分母；证据不全显示未确认。
- 地区仅表示核验后的发布账号辖区，不宣称事件发生地；国管局单列中央机关。
- 旧台账和未知提交结果不被补成虚构成功；日志保留 run_id，读者卡片不显示。
- HTML 自包含、无上传行为；所有原文按文本安全渲染，人工判断仅保存在本机，可导出评审结果。

## Review Focus

- 14篇、3重复、11新增的实例应呈现新增5摘要就绪+6低分；原8 not_needed不套到新增分母。
- 正文不足、模型拒答、重复指向跨日旧行、同批多个候选指向同一新行、提交确认丢失、零篇。
- 新旧台账兼容，通知重试不改变冻结结果；输出不泄漏供应商错误或凭据。
- 141候选与111生产新增清晰区分；40高分不等同已经人工判定符合业务需求。
- 省级聚合与市级来源可展开，地区统计不得把重复转载归入新增来源。
